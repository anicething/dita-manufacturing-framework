## Approval Authority by Change Type

### Content Changes

| Change Type | Description | Authority | Timeline | Notes |
|---|---|---|---|---|
| **Typo/Spelling** | Minor spelling or formatting fixes | Writer → Auto-merge | Same day | No review needed |
| **Example Update** | Update examples, code samples | Writer → SME | 2 days | SME verifies accuracy |
| **Technical Content** | Update procedures, instructions | Writer → SME → Product Manager | 5 days | Requires SME approval |
| **Product Update** | Updates for new version | Writer → SME → Product Manager | 5 days | Per product release schedule |
| **Compliance Update** | Legal/safety changes | Writer → Compliance → DGC | 3 days | Urgent escalation |

### Structural Changes

| Change Type | Description | Authority | Timeline | Notes |
|---|---|---|---|---|
| **New Topic** | Create new topic file | Writer → Architect → Product Manager | 8 days | Full approval workflow |
| **Map Reorganization** | Change topic hierarchy | Writer → Architect → DGC | 10 days | DGC review required |
| **New Content Type** | Create specialized topic type | Architect → DGC | 30 days | Strategic decision |
| **Metadata Change** | Modify metadata standards | Architect → DGC | 30 days | Impacts all topics |

### Governance Changes

| Change Type | Description | Authority | Timeline | Notes |
|---|---|---|---|---|
| **Style Guide Update** | Modify writing standards | Architect → DGC | 30 days | All writers affected |
| **Process Change** | Modify approval workflow | Architect → DGC | 30 days | Strategic review |
| **Tool Change** | Adopt new tool/platform | IT Lead → DGC | 60 days | Budget review required |
| **Specialization** | New DITA specialization | Architect → DGC | 60 days | Technical evaluation |

## Escalation Path

```
Review overdue?
  ↓
1. Send reminder (1 day late)
  ↓
2. Escalate to reviewer's manager (2 days late)
  ↓
3. Escalate to Director Tech Comms (3 days late)
  ↓
4. DGC review at monthly meeting (4+ days late)
```

---

## Review Criteria

### For Content Approvals
- ✅ Metadata complete
- ✅ No spelling errors
- ✅ No broken links
- ✅ Follows style guide
- ✅ Topic type appropriate
- ✅ No security violations
- ✅ Complies with ISO requirements

### For Structural Approvals
- ✅ All above plus:
- ✅ Proper DITA structure
- ✅ Reuse opportunities identified
- ✅ Maps properly organized
- ✅ Localizable for translation

### For Governance Approvals
- ✅ All above plus:
- ✅ Impact assessment completed
- ✅ Risk analysis done
- ✅ Budget impact documented
- ✅ Timeline realistic
- ✅ DGC consensus reached
