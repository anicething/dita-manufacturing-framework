## 执行摘要

本章程为整个制造企业建立 DITA（达尔文信息分类架构）采用的治理框架。它定义了所有技术文档的角色、职责、决策权限以及合规要求。

## 1. 愿景与目标

### 愿景
为所有产品技术文档创建**单一真实数据源**，实现：
- 跨产品的 35-40% 内容复用率
- 本地化成本降低 30-35%
- 产品文档更快的上市时间
- 通过一致且可搜索的文档，提升客户满意度
- 具备审计追踪的完全 ISO 合规

### 战略目标
1. **内容集中化** — 18 个月内将所有文档迁移至 DITA 格式
2. **最大化复用** — 为通用主题建立共享内容仓库
3. **确保质量** — 符合 ISO 标准的审查与批准工作流
4. **支持本地化** — 同时支持 8 种以上语言
5. **自动化发布** — 用于即时分发的 CI/CD 流水线
6. **衡量成效** — 按季度跟踪关键绩效指标

## 2. 治理结构

### 2.1 文档治理委员会 (DGC)

**创始成员:**
- **技术传播总监**（主席）
- **产品经理**（每个产品线各一名代表）
- **质量保证主管**
- **本地化经理**
- **IT/基础设施主管**（工具与发布）
- **合规/法务代表**
- **客户支持主管**

**职责:**
- 审查与批准 DITA 治理政策
- 解决跨产品内容冲突
- 批准新的专用化领域或内容域
- 审查季度 KPI 并调整策略
- 监督本地化战略
- 确保 ISO 合规

**会议频率:** 每月一次（第一个星期四，上午 10 点）

### 2.2 架构与标准团队

**成员:**
- **DITA 架构师**（1 人全职）
- **资深技术写作师**（1 人全职）
- **元数据管理师**（0.5 人全职）
- **工具管理员**（1 人全职）

**职责:**
- 维护样式指南与模板
- 定义元数据标准
- 设计信息架构
- 在批准前审查主题结构
- 管理专用化领域

**会议频率:** 每双周一次

## 3. 内容所有权与责任制

### 内容分类

| 类别 | 负责人 | 审批人 | 更新频率 |
|------|--------|--------|----------|
| **共享/通用主题** | DITA 架构师 | DGC | 按需 |
| **产品专属主题** | 产品写作师 | 产品经理 | 每个版本 |
| **合规/法务主题** | 合规法务 + 产品写作师 | 法务审查 | 季度 |
| **API/技术参考** | 开发者关系 | 技术负责人 | 每个版本 |
| **发布说明** | 产品经理 + 写作师 | 产品经理 | 每个版本 |
| **知识库/常见问题** | 客户支持 | 支持经理 | 每月 |

### 变更权限矩阵

```
轻微更新（拼写错误、示例修正）：  写作师 → 自动合并
内容更新（技术性）：               写作师 → 产品经理 → 合并
结构变更（映射、主题）：           写作师 → 架构师 → DGC → 合并
专用化变更：                      架构师 → DGC → 合并
样式指南变更：                     架构师 → DGC → 合并
```

## 4. 主题开发与批准工作流

### 标准工作流

```
1. 计划
2. 起草（写作师在 Git 分支中创建主题）
3. 主题专家审查（SME 审查技术准确性）
4. 合规检查（法务/合规审查 ISO 合规性）
5. 编辑审查（架构师/资深写作师审查结构与样式）
6. 批准（产品经理签署确认）
7. 发布（自动合并至主分支，触发 CI/CD 流水线）
8. 分发（多渠道发布：Web、PDF、移动端等）
9. 本地化（自动提取至翻译系统）
10. 监控（跟踪使用量、反馈、问题）
```

### 服务水平协议 (SLA)

| 任务 | 截止时间 | 负责人 |
|------|----------|--------|
| 起草主题 | 3 个工作日 | 写作师 |
| SME 审查 | 2 个工作日 | 主题专家 |
| 合规检查 | 1 个工作日 | 合规团队 |
| 编辑审查 | 1 个工作日 | 架构师 |
| 最终批准 | 1 个工作日 | 产品经理 |
| **总计发布用时** | **< 8 个工作日** | - |

## 5. ISO 合规要求

### 5.1 ISO 27001（信息安全）
所有文档存储与传输必须加密。访问控制基于角色。审计日志必须保留至少 12 个月。每季度进行渗透测试。

### 5.2 ISO 9001（质量管理）
文档化的质量流程。所有主题必须经过审查与批准。必须跟踪缺陷与纠正措施。持续改进流程必须到位。

### 5.3 ISO 14001（环境管理）
优先采用数字优先的分发方式（减少纸张使用）。因文档流程改进而产生的环境影响削减需量化。供应链文档要求必须包含环境条款。

### 5.4 文档可追溯性

所有文档必须包含：文档编号、版本、最后更新日期、作者、审查状态、分类、审查频率。

## 6. 内容标准与合规

### 6.1 强制性元数据
每个主题必须包含：docid、audience、product、version、status、created、revised、reviewed-by、security-level、revision-reason

### 6.2 主题类型要求

**概念主题（占内容 40%）** — 回答"是什么……"，图表，交叉引用
**任务主题（占内容 40%）** — 分步说明，前置条件，预期结果，故障排除
**参考主题（占内容 20%）** — 命令/配置文档，数据表，API 规格说明

## 7. 关键绩效指标 (KPI)

| 指标 | 目标 | 方法 | 负责人 |
|------|------|------|--------|
| 内容复用率 | 35-40% | 人工审计 | 架构师 |
| 发布周期 | < 2 小时 | CI/CD 日志 | 工具管理员 |
| 翻译时间 | < 1 周 | TMS 报告 | 本地化经理 |
| 客户满意度 | > 4.0/5.0 | 问卷调查 | 支持主管 |
| 错误率 | < 2% | QA 审计 | QA 主管 |
| 主题完整度 | > 95% | 元数据审查 | 写作师 |
| 本地化成本 | 降低 30-35% | 预算分析 | 财务 |
| 更新时间 | < 24 小时 | Git 日志 | 写作师 |
