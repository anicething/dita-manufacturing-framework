# 内容所有权矩阵

**文档编号:** GOV-002  
**版本:** 1.0  
**最后更新:** 2026-06-06  
**状态:** 已批准  
**分类:** 仅限内部使用

---

## 概述

本文档定义整个 DITA 制造框架中所有内容类型的所有权、责任制以及审批路径。它为谁负责创建、维护和批准每条内容建立了明确的责任划分。

---

## 1. 共享内容所有权

共享内容涵盖跨多个产品线的通用组件、安全指南和维护流程。

| 内容类型 | 负责人 | 审批人 | 更新频率 | 描述 |
|----------|--------|--------|----------|------|
| 安全警告与防护措施 | DITA 架构师 + QA 写作师 | DGC + 合规官 | 季度 | 所有产品通用的标准安全协议与警告 |
| 安装概述 | DITA 架构师 | 产品经理（全部） | 每发布版本 | 适用于所有产品线的高级安装架构 |
| 维护排程 | 资深写作师 | DGC | 月度 | 预防性维护排程与间隔 |
| 故障排除框架 | 资深写作师 + QA 写作师 | DITA 架构师 | 按需 | 故障排除工作流的标准方法论 |
| 合规与认证 | 合规代表 + DITA 架构师 | DGC + 法务 | 季度 | ISO/监管合规要求与认证状态 |
| 术语表（企业级） | 元数据管理师 | DGC | 季度 | 经批准的术语及定义的企业级术语表 |
| DITA 编写标准 | DITA 架构师 | DGC | 按需 | 适用于所有写作师的结构与元数据标准 |

## 5. 角色与职责

### 5.1 DITA 架构师
- **主要职责:** 定义并维护信息架构、DITA 专用化、样式指南与模板
- **所有权范围:** 所有共享/通用内容、所有产品的结构审查
- **审批权限:** 结构变更、专用化定义、样式指南更新
- **汇报对象:** 技术传播总监
- **工作量:** 全职

### 5.2 产品经理（每个产品线）
- **主要职责:** 拥有内容工作的产品战略与优先级排序
- **所有权范围:** 特定产品的发布说明、最终批准签名
- **审批权限:** 内容更新、发布批准、新内容请求
- **汇报对象:** 产品副总裁
- **工作量:** 0.2 人全职（每产品线）

### 5.3 资深写作师
- **主要职责:** 指导产品写作师，审查编辑质量，管理共享内容
- **所有权范围:** 维护排程、故障排除框架、管理员指南
- **审批权限:** 编辑审查、产品质量签名
- **汇报对象:** 技术传播总监
- **工作量:** 全职

### 5.4 产品写作师（每个产品线）
- **主要职责:** 为分配的产品线创建并维护特定产品的文档
- **所有权范围:** 其产品线的所有特定产品内容
- **审批权限:** 无（需产品经理批准）
- **汇报对象:** 技术传播总监（实线）、产品经理（虚线）
- **工作量:** 全职

### 5.5 QA 写作师
- **主要职责:** 关注质量、安全与校准文档
- **所有权范围:** 校准程序、安全数据表联合体、QA 审计
- **审批权限:** 对安全与质量相关内容的否决权
- **汇报对象:** QA 主管（实线）、技术传播总监（虚线）
- **工作量:** 全职

### 5.6 客户支持主管
- **主要职责:** 拥有面向客户的知识库与常见问题内容
- **所有权范围:** 知识库文章、常见问题、支持文档
- **审批权限:** 所有面向客户支持内容的批准
- **汇报对象:** 客户体验副总裁
- **工作量:** 0.3 人全职

### 5.7 开发者关系
- **主要职责:** 为开发者受众创建并维护 API 与技术参考文档
- **所有权范围:** 所有产品的 API 参考、数据库模式、固件参考
- **审批权限:** 技术准确性（架构审查）
- **汇报对象:** 技术负责人
- **工作量:** 0.5 人全职

## 6. 所有权转移流程

当内容所有权需要变更时：

1. **发起:** 现任负责人或要求者在 DGC 会议上提交所有权转移请求
2. **评估:** DGC 评估新负责人的工作负载影响与资格
3. **过渡计划:** 创建为期 2 周的过渡计划，包括知识转移会议
4. **批准:** DGC 以简单多数投票批准转移
5. **文档记录:** 更新本矩阵文档与元数据以反映新所有权
6. **沟通:** 向所有受影响的利益相关方发布通知

---

## 7. 争议解决

如果内容创建者与审批人之间存在分歧：

1. 创建者与审批人尝试直接解决
2. 若未解决，在 24 小时内升级至 DITA 架构师调解
3. 若持续存在，在下一个排期的 DGC 会议（或紧急情况下召开特别会议）上提交 DGC
4. DGC 决定为最终决定，并记录以供未来参考
