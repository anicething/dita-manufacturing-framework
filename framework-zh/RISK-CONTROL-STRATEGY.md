## 1. 风险管理框架

### 1.1 目标

建立系统化的方法，用于在 DITA 框架的整个生命周期中——从初始实施到持续运营——识别、评估、控制和监控风险。

### 1.2 风险管理流程

```
识别 → 评估（可能性×影响） → 规划控制措施 → 实施 → 监控 → 评审 →（循环）
```

| 步骤 | 说明 | 负责人 | 频率 |
|------|------|--------|------|
| 识别 | 通过工作坊、审计、复盘发现潜在风险 | CoE 负责人 | 持续 |
| 评估 | 按可能性×影响打分，确定风险等级 | CoE 负责人 + DGC | 每月 |
| 规划控制 | 定义预防措施（主动）和应急措施（被动） | CoE 负责人 | 按风险 |
| 实施 | 执行控制措施，分配责任人 | 风险责任人 | 按计划 |
| 监控 | 跟踪风险指标和控制效果 | CoE 负责人 | 每周（自动化） |
| 评审 | 每季度重新评估风险等级，关闭已解决风险 | DGC | 每季 |

### 1.3 风险责任归属

| 角色 | 风险责任 |
|------|---------|
| **CoE 负责人** | 整体风险管理、升级处理 |
| **内容架构师** | 内容质量风险、元数据完整性 |
| **IT 负责人** | 技术/工具链风险、数据丢失 |
| **培训负责人** | 技能差距、采纳率风险 |
| **DGC（治理委员会）** | 组织风险、合规、战略 |
| **所有作者** | 内容质量风险（第一道防线） |

## 2. 风险分类与等级

### 2.1 风险评分矩阵

| 可能性 \ 影响 | 可忽略 (1) | 轻微 (2) | 一般 (3) | 重大 (4) | 灾难 (5) |
|-------------|-----------|---------|---------|---------|---------|
| **几乎确定 (5)** | 中 (5) | 高 (10) | 高 (15) | 极严重 (20) | 极严重 (25) |
| **很可能 (4)** | 低 (4) | 中 (8) | 高 (12) | 高 (16) | 极严重 (20) |
| **可能 (3)** | 低 (3) | 中 (6) | 中 (9) | 高 (12) | 高 (15) |
| **不太可能 (2)** | 低 (2) | 低 (4) | 中 (6) | 中 (8) | 高 (10) |
| **罕见 (1)** | 低 (1) | 低 (2) | 低 (3) | 中 (4) | 中 (5) |

### 2.2 风险等级定义

| 等级 | 分值范围 | 应对方式 | 上报要求 |
|------|---------|---------|---------|
| **低** | 1-3 | 接受——仅监控 | 登记在册即可 |
| **中** | 4-8 | 缓解——指定责任人，实施控制 | 每月评审 |
| **高** | 9-16 | 主动管理——专项控制计划 | 每周评审；向 DGC 报告 |
| **极严重** | 17-25 | 立即升级——高管介入 | 每日监控；紧急 DGC 会议 |

### 2.3 风险编号规则

```
RISK-XXX-[类别码]
实施风险: IMP
运营风险: OPS
内容风险: CON
技术风险: TEC
组织风险: ORG
```

| 级别 | 标准 | 响应时间 | 示例 |
|------|------|---------|------|
| **SEV-1** | 已发布内容包含安全关键错误 | 1 小时 | 错误的安全规程、缺少危险警告 |
| **SEV-2** | 构建流水线完全瘫痪，无法产出 | 4 小时 | CI/CD 故障、DITA-OT 崩溃 |
| **SEV-3** | 质量下降、部分输出或交付延迟 | 24 小时 | conref 断裂、DITAVAL 配置错误 |
| **SEV-4** | 小问题，有变通方案 | 1 周 | 外观格式问题、过时元数据 |

### 9.2 SEV-1 响应流程（安全关键）

```
1. 检测 — 自动检查/用户报告/审计发现安全错误
   ↓
2. 停止 — 立即暂停发布流水线（所有语言）
   ↓
3. 通知 — 邮件 + IM 通知：CoE 负责人、内容架构师、DGC 主席、法务
   ↓
4. 评估 — 内容架构师 + SME 确定影响范围（哪些主题、哪些产品）
   ↓
5. 修复 — 作者修正源主题；SME + 内容架构师批准
   ↓
6. 重发 — 紧急构建；跳过正常队列
   ↓
7. 通知 — 向所有受影响的利益相关方确认修复；如已分发则召回旧版
   ↓
8. 根因 — 5 个工作日内完成复盘；更新控制措施
```

### 9.3 SEV-2 响应流程（流水线宕机）

```
1. 检测 — 收到 CI/CD 失败告警
   ↓
2. 分类 — IT 负责人确定原因（DITA-OT 错误/CI/CD 系统宕机/插件问题）
   ↓
3. 恢复 — 尝试上次正常构建；如因 DITA-OT 升级导致则回滚
   ↓
4. 通知 — 告知 CoE 负责人和写作团队预计停机时间
   ↓
5. 手动回退 — 如自动构建宕机超 4 小时：使用本地 oXygen 发布
   ↓
6. 解决 — 部署根本原因修复；流水线绿灯
   ↓
7. 记录 — 将事故报告加入知识库
```

### 9.4 紧急联系树

```
SEV-1 安全问题：
  作者 → 内容架构师（1h 内）→ SME → DGC 主席 → 法务 → 高管
  升级时间：1h → 2h → 4h → 8h

SEV-2 流水线宕机：
  IT 值班 → IT 负责人（2h 内）→ CoE 负责人 →（超 8h）高管
  升级时间：2h → 4h → 8h → 24h

SEV-3 质量问题：
  作者 → 内容架构师（24h 内）→ 下一个构建周期修复
  升级时间：24h → 48h → 下次 DGC 会议

SEV-4 小问题：
  记入问题跟踪器 → 下一次计划发布中修复
```

## 10. 监控与评审

### 10.1 风险评审节奏

| 类型 | 频率 | 参与人 | 议程 |
|------|------|--------|------|
| 运营风险评审 | 每周 | CoE 负责人、IT 负责人、内容架构师 | RAG 状态、新增风险、控制效果 |
| DGC 风险评审 | 每月 | 全体 DGC | 高/极严重风险、缓解进展 |
| 季度风险深度分析 | 每季 | CoE 负责人 + DGC | 重新评分所有风险、关闭已解决风险 |
| 年度风险刷新 | 每年 | CoE 负责人 + 所有责任人 | 全面重新评估、识别新风险 |

### 10.2 风险仪表盘指标

| 指标 | 目标值 | 数据来源 |
|------|--------|---------|
| 未关闭的高/极严重风险数量 | ≤ 3 | 风险登记册 |
| 风险解决时间 | 高风险 ≤ 30 天，极严重 ≤ 14 天 | 事故跟踪器 |
| 控制措施有效性评分 | ≥ 80% | 季度审计 |
| 每季度 SEV-1 事故数 | 0 | 事故日志 |
| 风险登记册完整度 | 100%（所有类别已填写） | 季度评审 |

### 10.3 风险关闭标准

风险可在以下情况关闭：
- 该风险已实际发生且已完全解决，或
- 在已实施控制措施的情况下，可能性已降至"罕见"，或
- 相关系统/流程已停用
- 关闭须经 DGC 批准

### 10.4 升级路径

```
风险责任人 → CoE 负责人 → DGC 主席 → 高管
（升级时间按第 9.4 节定义）
```
