# DITA 制造框架
## 培训第一模块：基础与治理

**培训对象：** 技术文档工程师、编辑、内容负责人
**时长：** 4 小时

制造企业 — 文档治理委员会

---

## 什么是 DITA？

**达尔文信息分类架构（Darwin Information Typing Architecture）**

DITA 是基于 XML 的标准，用于创建、管理和发布技术文档。

核心原则：
- **面向主题** — 内容模块化，而非整书式
- **设计即复用** — 一次编写，随处使用
- **内容分类** — 25+ 种专用类型可供选择
- **专门化** — 可根据领域需求扩展标准
- **多渠道输出** — 同一来源 → HTML5、PDF、移动端、LMS

> 本框架 v1.1 采用 **13 种主题类型**，分为三个梯队。

---

## 制造业为什么需要 DITA？

| 挑战 | DITA 解决方案 |
|------|---------------|
| 多产品文档共用相同内容 | **内容复用**（目标 35–40%） |
| 多语言（9 种语言） | **主题级本地化** 通过 xml:lang |
| ISO 合规（27001/9001/14001） | **元数据 + 危害声明** 审计追踪 |
| 50+ 人的文档团队 | **模块化编写** 支持并行工作 |
| 复杂故障排查需求 | **专用故障排查类型** |
| 安全警告必须可审计 | **机械行业域危害元素** |
| 9 种语言的术语翻译 | **每术语独立术语条目类型** |

## 变更权限矩阵

| 类型 | 示例 | 批准人 | SLA |
|------|------|--------|-----|
| **第 1 类：轻微** | 错别字、格式 | **作者**（自助） | < 1 天 |
| **第 2 类：中等** | 数值更新（扭矩参数） | **技术主管** | < 3 天 |
| **第 3 类：重大** | 新增章节、重组结构 | **全面治理审查** | < 5 天 |
| **第 4 类：关键** | 安全、合规 | **总监 + 合规** | 48 小时（强制等待） |

> 新增主题类型（如为某产品线添加危害声明）= **第 3 类**变更。

## 内容架构 — 从 3 类到 13 类

v1.0 仅有 3 种类型。v1.1 扩展到 **13 种类型，分三个梯队**：

```
第一梯队 — 核心（内容量的 80%）
  概念（Concept）| 任务（Task）| 参考（Reference）

第二梯队 — 专门化（15%）
  故障排查（Troubleshooting） ← 新增：按症状诊断问题
  术语条目（Glossary Entry）  ← 新增：可复用、可翻译的术语
  危害声明（Hazard Statement）← 新增：ISO 合规的安全警告
  任务前置条件（Task Req.）   ← 新增：结构化前置条件
  主题方案（Subject Scheme）  ← 新增：元数据值治理

第三梯队 — 高级（5%）
  Bookmap                     ← 新增：印刷/PDF 出版物结构
  学习对象（Learning Object） ← 新增：e-Learning 模块
```

> 详见 `02-ARCHITECTURE/04-EXTENDED-TOPIC-TYPES.md`

## 选择决策树

```
这份内容是什么类型？
│
├─ 理解/解释性内容？          → 概念（Concept）

└─ 元数据治理？               → 主题方案（Subject Scheme）
```

## Subject Scheme — 元数据治理

**文件：** `02-ARCHITECTURE/05-SUBJECT-SCHEME-GUIDE.md`

Subject Scheme 强制执行**受控词汇表**：

```
没有 Subject Scheme：          有 Subject Scheme：
  audience="Operator"            audience="operator" ✅
  audience="操作员"              audience="operator" ✅
  audience="operators"           ✗ 验证错误
```

**带来的好处：**
- oXygen 中提供下拉列表 — 选择即可，无需手打
- CI/CD 自动验证 — 错误值阻止构建
- 一致的报告 — 无需手动数据清洗

> 模板：`06-TEMPLATES/12-SUBJECT-SCHEME-TEMPLATE.ditamap`

## 重点：故障排查主题

**解决的问题：** 之前维修手册被写为任务主题，但维修不是单一路径——一个症状可能有多种原因。

```
故障排查主题结构：
├── 条件："报警 700016 — 冷却液压力 < 0.3 MPa"
├── 原因 1（80%）：过滤器堵塞
│   └── 修复：清洁或更换过滤器滤芯
├── 原因 2（15%）：泵叶轮损坏
│   └── 修复：更换泵组件
└── 原因 3（5%）：冷却液不足
    └── 修复：补充冷却液
```

> **模板：** `06-TEMPLATES/06-TROUBLESHOOTING-TEMPLATE.dita`
> **示例：** `examples/topics/zh-CN/new-types/ALARM-700016-TROUBLESHOOTING.dita`

---

## 重点：术语条目

**解决的问题：** v1.0 有一个 Markdown 术语表——不可翻译、不可复用。现在每个术语是一个独立的 DITA 主题。

```
术语条目结构：
├── 术语："锁定/挂牌（LOTO）"
├── 定义："在维护操作前隔离能源的安全程序..."
├── 替代形式：缩略词 → LOTO
└── 相关术语：互锁、零能量状态
```

**对 9 语言翻译为什么重要：**
- TMS 识别每个术语为一个可翻译单元
- 一个术语的更改不影响其他术语
- 术语可通过 `conref` 被任何主题引用

> **模板：** `06-TEMPLATES/07-GLOSSARY-ENTRY-TEMPLATE.dita`
> **示例：** `examples/topics/zh-CN/new-types/GLOSS-LOTO.dita`

---

## 重点：危害声明（机械行业域）

**解决的问题：** 写在概念主题中的散文式安全警告，合规审计不可见。结构化危害元素是机器可读的，可提取用于 GB/T 15706 审计。

```
危害声明结构：
├── 类型：注意 / 警告 / 危险 / 提示
├── 危害类型："飞溅的切屑"
├── 后果："严重眼部伤害"
├── 避免方法："佩戴带侧护板的安全护目镜"
├── 风险评估：严重性 × 概率表
└── 标准参考：GB/T 15706、GB/T 16855.1
```

> **模板：** `06-TEMPLATES/08-HAZARD-STATEMENT-TEMPLATE.dita`
> ISO 审计员可以从文档集中以编程方式提取所有危害声明。

## 重点：Subject Scheme

**解决的问题：** 元数据质量。没有它，`audience` 可能在 1000 个主题中出现 5 种不同的写法。

```
Subject Scheme 管控的内容：
┌──────────────────────────────────────────┐
│  属性                受控值              │
├──────────────────────────────────────────┤
│  audience            operator,           │
│                      maintenance,        │
│                      engineer,           │
│                      field-service,      │
│                      trainer, all        │
├──────────────────────────────────────────┤
│  content-type        concept, task, ref, │
│                      troubleshooting,    │
│                      gloss, hazard,      │
│                      learning            │

```

## 参考答案

1. **13 种。** 第二梯队：故障排查、术语条目、危害声明、任务前置条件、Subject Scheme
2. 故障排查**按症状捕获多种可能原因**，每种原因对应修复步骤。任务假设单一固定路径。
3. 每个术语必须独立**可翻译**（9 种语言）、通过 conref **可复用**、TMS **可识别**。
4. **强制执行受控词汇表** — oXygen 下拉、CI/CD 验证、报告一致。
5. **Danger**（死亡）、**Warning**（重伤）、**Caution**（轻伤）、**Notice**（财产损失）
