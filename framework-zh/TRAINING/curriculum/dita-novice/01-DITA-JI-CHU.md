# DITA 是什么？

**Darwin Information Typing Architecture** — 达尔文信息分类架构

> **DITA** 是一种基于 XML 的开放标准，用于创建、管理和发布模块化、可复用的技术文档内容。

三个关键词：
- **Darwin** — 继承与专用化机制（像达尔文进化论一样可衍生）
- **Information Typing** — 按照信息类型组织内容（概念型、任务型、参考型）
- **Architecture** — 一套完整的文档体系架构，而非仅标记语言

| 年份 | 里程碑 |

| 2015 | **DITA 1.3** 发布（当前版本），引入 troubleshooting、scoping、MathML |
| 2023 | DITA 2.0 委员会草案（正在推进中） |

# 核心理念：基于主题的写作

<!-- _class: keypoint -->

## 不是"写一本书"，而是"编写一个个独立的话题模块"

| 传统文档思维 | DITA 主题思维 |
|-------------|--------------|
| 一本书从头到尾 | 独立、自包含的主题 |
| 内容耦合在一个文件 | 每个 XML 文件 = 一个主题 |
| 章节线性组织 | 通过导航图灵活组合 |
| 内容一次使用 | 一个主题可复用上千次 |
| 格式与内容混排 | 内容与展示分离 |

# 为什么制造业需要 DITA？

| 价值维度 | 具体收益 | 数据参考 |
|----------|----------|----------|
| **内容复用** | 一次编写，多次使用 | 降低 35-40% 的创建成本 |
| **单一源发布** | 一份源文件输出多种格式 | PDF / HTML5 / EPUB / Markdown |
| **多渠道输出** | 支持印刷、Web、移动端 | 一次构建，多终端交付 |
| **ISO 合规** | 符合 ISO/IEC 26514 等标准 | 可追溯、可审计 |
| **本地化效率** | 内容与翻译记忆集成 | 翻译成本降低 25-50% |

# DITA vs 传统文档工具

| 特性 | DITA (XML) | MS Word | Adobe FrameMaker | 静态 PDF |
|------|-----------|---------|-----------------|-----------|
| 内容复用 | 原生支持 | 复制粘贴 | 文本插入 | 不可能 |
| 版本控制 | Git/CCMS | 文件名版本号 | 有限支持 | 无 |
| 自动发布 | DITA-OT 构建 | 手动 | 手动 | N/A |
| 多格式输出 | 一键多格式 | 另存为 | 有条件 | 单格式 |
| 协作编辑 | 任意文本编辑器 | Word 多人 | 需要许可 | 不适用 |
| 结构化验证 | DTD/XSD 自动验证 | 依赖人工 | 部分验证 | 无 |

# DITA 内容生命周期

```
┌─────────────────────────────────────────┐
│           DITA 内容生命周期              │
├─────────┬──────────┬─────────┬──────────┤
│  编写   │   管理   │  发布   │  分发    │
│         │          │         │          │
│ oXygen  │  CCMS    │ DITA-OT │ PDF      │
│ Editor  │  Git     │ 构建    │ HTML5    │
│ 模板    │  分支    │ 管道    │ 移动端   │
│ 验证    │  评审    │         │ 门户     │
└─────────┴──────────┴─────────┴──────────┘
```

- **编写**：使用 XML 编辑器基于模板创建主题
- **管理**：通过 CCMS 或 Git 进行版本管理和评审
- **发布**：DITA-OT 自动化构建多格式输出
- **分发**：将交付物推送到各终端平台

# 关键概念速览

| 概念 | 解释 | 类比 |
|------|------|------|
| **Topic (主题)** | 独立、自包含的信息单元 | 乐高积木块 |
| **Map (导航图)** | 组织主题的目录结构 | 乐高说明书 |
| **Metadata (元数据)** | 描述内容属性的数据 | 食品营养成分表 |
| **Conref (内容引用)** | 引用并复用另一个元素的内容 | 编程中的 `#include` |
| **Specialization (专用化)** | 从通用类型派生专用类型 | 类的继承 |

# 制造业真实案例：CNC 机床文档

**传统方式（无 DITA）**：
- 30 份独立 Word 文档，总计约 5000 页
- 安全警告在每个文档中重复粘贴
- 每次产品升级需手动更新所有文档
- 翻译周期 6 个月

**DITA 方式**：
- 1 个安全警告主题 + 2,500 个功能主题
- 通过 15 个导航图组合为不同交付物
- 修改安全警告：1 处更新，15 份文档自动同步
- 翻译周期缩短至 2 个月

# DITA 工具链全景

| 工具类别 | 代表产品 | 用途 |
|----------|----------|------|
| **XML 编辑器** | oXygen XML Editor / XMetaL | 主题和导航图创作 |
| **CCMS (内容管理系统)** | Tridion Docs / Ixiasoft / easyDITA | 版本控制、工作流、协作 |
| **发布引擎** | DITA-OT / oXygen Publishing Engine | XML 到 PDF/HTML5/EPUB 转换 |
| **TMS (翻译管理)** | SDL / MemoQ / XTM | 翻译记忆、术语管理 |
| **样式开发** | XSLT / CSS / XSL-FO | 自定义 PDF 和 HTML 样式 |
| **版本控制** | Git + GitHub/GitLab | 源代码级别版本管理 |

# DITA-OT 简介

**DITA Open Toolkit** — 开源 DITA 发布引擎

- 由 IBM 最初开发，现由 DITA-OT 社区维护
- 支持多种输出格式：PDF / HTML5 / EPUB / Markdown 等
- 插件架构：可扩展新格式和功能
- 命令行构建 + CI/CD 集成

```bash
# 基本构建命令
dita --input=my-map.ditamap --format=pdf --output=./output
```

# 为什么选择 DITA？

<!-- _class: keypoint -->

1. **开放标准**：不绑定特定厂商，投资有保障
2. **经过验证**：20+ 年行业实践，大型企业广泛采用
3. **生态系统成熟**：工具、社区、服务商完善
4. **制造业适配**：ISO 合规、结构化、可追溯
5. **成本效益**：复用和自动化显著降低 TCO
