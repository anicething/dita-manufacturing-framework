# 第一部分
## 内容质量指标基础

---

## 为什么制造业需要内容指标

制造业文档是**产品安全与合规的生命线**。

- 一份 CNC 操作手册的错误可能导致工伤事故
- 物料清单 (BOM) 的版本不一致引发停产损失
- 多语言翻译滞后影响全球市场准入

**核心原则**：你无法改进你无法测量的东西。

---

## 制造业文档的独特挑战

| 挑战 | 传统方案 | 指标驱动方案 |
|------|---------|-------------|
| 多条产品线并行 | 每产品独立编写 | 测量复用率，驱动共享 |
| 法规频繁更新 | 手工合规检查 | 自动合规评分 |
| 翻译成本高昂 | 全量翻译 | 基于复用率的翻译优化 |
| 文档过时 | 无追踪机制 | 内容新鲜度自动告警 |
| 质量参差 | 主观评估 | 多维量化评分 |


# 第二部分
## 复用率计算与目标

---

## 什么是内容复用率

内容复用率衡量**跨交付件共享的主题比例**。

```
复用率 = (复用主题数 / 总主题数) × 100%

其中：
- 总主题数 = 所有 .dita 文件的总数
- 复用主题数 = 被 2 个及以上 ditamap 引用的主题数
```

制造业基准：优秀项目复用率 **35-40%**

---

## 复用率的三个层次

```
Level 1: 文件级复用
  ┌── mapA.ditamap ──┐     ┌── mapB.ditamap ──┐
  │  topic-001.dita  │ ←→ │  topic-001.dita  │  ← 同一文件
  └──────────────────┘     └──────────────────┘

Level 2: 元素级复用 (conref)
  ┌── topic-A.dita ──────────────┐
  │  <p conref="shared.dita#warn/safety"/>  │
  └──────────────────────────────┘

Level 3: 段落级复用 (conkeyref)
  ┌── map.ditamap ─────────────────┐
  │  <keydef keys="safety"         │
  │   href="safety-lib.dita"/>     │
  └────────────────────────────────┘
```

---

## 复用率计算示例：注塑机文档

<!-- _class: exercise -->

```
项目结构：
  /products/injection-molding/
    ├── operator-guide.ditamap     ← 引用 45 个主题
    ├── maintenance-manual.ditamap ← 引用 38 个主题
    ├── parts-catalog.ditamap      ← 引用 52 个主题
    └── topics/
          ├── safety/              ← 12 个主题（全部被引 ≥2 次）
          ├── operations/          ← 30 个主题（15 个被引 ≥2 次）
          ├── maintenance/         ← 25 个主题（20 个被引 ≥2 次）
          └── reference/           ← 18 个主题（5 个被引 ≥2 次）
```

计算复用率 = (12 + 15 + 20 + 5) / (12 + 30 + 25 + 18) = 52/85 = **61.2%**

## 复用率行业基准

| 行业 | 低 | 中 | 高 | 卓越 |
|------|---|----|----|------|
| 通用制造业 | < 15% | 15-25% | 25-35% | > 35% |
| 半导体设备 | < 20% | 20-30% | 30-40% | > 40% |
| 汽车制造 | < 25% | 25-35% | 35-45% | > 45% |
| 医疗器械 | < 15% | 15-25% | 25-35% | > 35% |
| 航空航天 | < 20% | 20-30% | 30-40% | > 40% |

**框架目标**：第一年达到 25%，第二年达到 35%，第三年达到 40%+

---

## 提升复用率的六大策略

1. **共享安全库** — 所有安全警告集中管理，conref 引用
2. **通用操作库** — 启动/停机/急停等通用步骤模板化
3. **术语表统一** — 全公司统一术语定义，消除重复描述
4. **参考信息集中** — 规格参数、物料号单一来源
5. **跨产品映射** — 同系列产品共享基础操作主题
6. **模板驱动创作** — 新主题从高复用模板开始

---

## 复用率陷阱与对策

| 陷阱 | 表现 | 对策 |
|------|------|------|
| **伪复用** | 为复用而复用，内容不适合 | 质量优先，不强制 100% 复用 |
| **过度碎片化** | 主题拆分过细，管理复杂 | 主题保持"自包含"原则 |
| **版本漂移** | 复用主题更新后，引用方不知情 | 实施变更通知机制 |
| **翻译浪费** | 修改一个词导致全部引用方重译 | 使用翻译记忆锁定不变段落 |
| **内容稀释** | 为通用而通用，失去针对性 | 使用 conditional processing |

# 第三部分
## 覆盖率分析

---

## 什么是内容覆盖率

覆盖率衡量**文档对所有需要覆盖的主题的完整程度**。

两种核心类型：
- **主题覆盖率** — 已写主题 / 应写主题
- **映射覆盖率** — 已实现映射 / 目标映射数

---

## 主题覆盖率计算

```
主题覆盖率 = (已存在的 .dita 文件数 / 
               内容清单定义的主题数) × 100%
```

示例：CNC 铣床手册需要 120 个主题，已有 108 个 → **90% 覆盖率**

这 12 个缺失的主题是什么？
- 4 个：尚未发布的 beta 功能
- 5 个：等待工程提供规格数据
- 3 个：遗留老版本，不再适用 ← 应从清单中移除

---

## 内容清单管理

每个产品映射应有对应的**内容清单表**：

| 清单 ID | 主题标题 | 类型 | 状态 | 负责人 | 截止日期 |
|---------|---------|------|------|--------|---------|
| INV-001 | 安装前检查清单 | task | ✅ 已发布 | 张三 | 2025-Q1 |
| INV-002 | 电气接线图 | reference | ✅ 已发布 | 李四 | 2025-Q1 |
| INV-003 | 激光校准步骤 | task | 🔄 编写中 | 王五 | 2025-Q2 |
| INV-004 | 固件更新流程 | task | ⬜ 未开始 | 赵六 | 2025-Q3 |

## 覆盖率不足的代价

<!-- _class: note -->

制造业真实案例：

某自动化设备厂商，因安装手册覆盖率为 72%（缺 28% 主题），导致：
- 每季度约 **40 次** 安装现场技术支持呼叫
- 每次呼叫平均成本 **$850**（差旅 + 工时）
- 季度额外成本 = 40 × $850 = **$34,000**
- 将覆盖率提升至 92% 后，呼叫数降至 12 次/季
- **年节省 $105,600**

---

<!-- _class: keypoint -->

## 关键要点：覆盖率

- 覆盖率分为主题覆盖率和映射覆盖率
- 需要维护内容清单来跟踪缺失主题
- 目标：主题覆盖率 >= 90%，映射覆盖率 >= 85%
- 自动化采集是持续跟踪的前提
- 覆盖率不足直接导致支持成本增加

# 第四部分
## 可读性指标

---

## 为什么制造业文档需要可读性测量

制造业文档的读者群体多样：

- **操作工** — 可能只有高中学历，英语非母语
- **维护技师** — 技术教育背景，需要精确步骤
- **工程师** — 本科以上，能理解复杂技术术语
- **安全审核员** — 合规导向，需要特定格式

**一个可读性分数不能满足所有读者需求。**

---

## Flesch-Kincaid 可读性公式

```
Flesch Reading Ease (FRE):
  FRE = 206.835 - 1.015 × (总词数/总句数) 
                 - 84.6 × (总音节数/总词数)

Flesch-Kincaid Grade Level (FKGL):
  FKGL = 0.39 × (总词数/总句数) 
       + 11.8 × (总音节数/总词数) 
       - 15.59
```

中文适配：使用**字/句比**和**复音词比例**替代原文公式

---

## 制造业文档可读性目标

| 文档类型 | 目标读者 | FK 年级 | FRE 得分 |
|---------|---------|---------|----------|
| 安全警告 | 全体人员 | 6-8 | 60-70 |
| 操作步骤 | 操作工 | 8-10 | 50-60 |
| 维护手册 | 技师 | 10-12 | 40-50 |
| 技术规格 | 工程师 | 12-14 | 30-40 |
| 合规文件 | 审核员 | 14+ | 0-30 |

---

## SMOG 指数

```
SMOG Grade = 1.0430 × sqrt(30 × (多音节词数/句子数)) + 3.1291

多音节词定义：≥ 3 个音节的词
```

SMOG 比 Flesch-Kincaid 更严格，适用于安全关键文档。

**制造业实践**：安全警告使用 SMOG 验证，确保所有人员可理解。

---

## 中文可读性测量工具

中文可读性不能直接套用英文公式，推荐方法：

1. **字频分析** — 高频字 vs 低频字比例
2. **句长分布** — 短句 (< 15 字) vs 长句 (> 40 字)
3. **术语密度** — 专业术语占总词数的比例
4. **段落长度** — 平均段落字数

**目标**：操作文档每句不超过 25 字，每段不超过 4 句。

---

## 可读性自动化检查

```bash
# 集成到 CI/CD 流水线
dita readability-report \
  --input ./topics/ \
  --lang zh-CN \
  --format json \
  --output readability-report.json \
  --threshold FKGL:10
```

流水线配置：当 FKGL > 12 时，构建**警告**但不阻止发布。

---

## 可读性改善技巧

| 技巧 | 示例（改前） | 示例（改后） |
|------|------------|------------|
| 短句 | "在执行维护操作之前必须确保设备已经完全停止运行并且电源已经被切断" | "维护前请执行两步：1) 停止设备 2) 切断电源" |
| 主动语态 | "该参数可被系统管理员配置" | "系统管理员配置此参数" |
| 项目符号 | 连续 200 字无断点的步骤 | 编号列表，每步不超过 2 句 |
| 一致术语 | 控制面板 / 操作面板 / 面板混用 | 统一使用"控制面板" |
| 图示辅文 | 纯文字描述机床结构 | 文字 + 标注图 |

---

<!-- _class: keypoint -->

## 关键要点：可读性

- 中英文使用不同的可读性测量体系
- 安全关键文档优先使用 SMOG 指数
- 操作文档目标 FKGL 8-10 年级
- 自动化可读性检查集成到 CI/CD
- 改善技巧：短句、主动语态、项目符号、一致术语

# 第五部分
## 合规评分

---

## 什么是合规评分

合规评分是**文档满足法规、标准和内部要求的量化度量**。

制造业合规维度：
- **安全标准** — ISO 12100、ISO 13849
- **行业法规** — FDA 21 CFR Part 11、EU MDR
- **公司政策** — 安全警告格式、免责声明位置
- **翻译合规** — 目标市场语言覆盖
- **发布流程** — SLA 遵守情况

---

## 合规评分计算模型

```
合规评分 = Σ(维度权重 × 维度得分) / Σ(维度权重)

维度得分 = (合规项数 / 检查项总数) × 100

维度权重示例：
  安全标准: 30%
  行业法规: 25%
  公司政策: 20%
  翻译合规: 15%
  发布流程: 10%
```

**满分 100 分，目标 >= 95 分**

---

## 安全合规检查清单

<!-- _class: note -->

```
☑ 每个危险操作前有对应安全警告
☑ 安全警告使用标准化信号词(Danger/Warning/Caution)
☑ 安全警告包含：信号词 + 危险描述 + 后果说明 + 避免措施
☑ 所有安全符号符合 ISO 7010
☑ 急停步骤在所有操作文档中突出显示
☑ 个人防护装备(PPE)要求在每个程序前明确列出
☑ 残余风险声明包含在相关章节
☑ 安全警告标记为 conref 以保证一致性
```

---

## SLA 驱动的发布合规

制造业文档发布服务等级协议 (SLA)：

| SLA 指标 | 目标 | 严重 | 测量方式 |
|----------|------|------|---------|
| 紧急安全更新发布 | < 2 小时 | 超时即违规 | CI/CD 时间戳 |
| 产品发布文档同步 | 与产品同日 | 延迟 ≤ 24h | 产品发布日期 vs 文档发布日期 |
| 翻译交付 | < 1 周 | 超 3 天升级 | TMS 完成时间戳 |
| 缺陷修复发布 | < 48 小时 | P1 缺陷 < 4h | 缺陷关闭时间 |
| 法规更新响应 | < 5 工作日 | 依法规类型 | 法规生效日 vs 文档更新日 |

---

## 翻译合规评分

```
翻译覆盖率 = (已翻译主题数 / 需翻译主题数) × 100%

目标市场覆盖：
  必译语言: 100% 覆盖率 (目标市场法规要求)
  选译语言: 80% 覆盖率 (非法规但商业需要)
  
语言质量:
  LQA 评分 >= 95/100
  术语一致性 >= 98%
```

**制造业实践**：医疗器械进入欧盟市场，必须 100% 覆盖 24 种官方语言。

<!-- _class: keypoint -->

## 关键要点：合规评分

- 合规评分是量化文档合规性的核心指标
- 五维度：安全、法规、政策、翻译、发布
- 安全合规是最重要的维度（权重 30%）
- 发布 SLA：紧急更新 < 2 小时，翻译 < 1 周
- 自动化检查是持续合规的前提

# 第六部分
## 内容新鲜度与生命周期

---

## 内容新鲜度定义

内容新鲜度衡量**内容自最后审核或更新以来的时效性**。

```
新鲜度分数 = 1 - (自上次审核天数 / 审核周期天数)

示例：审核周期 180 天，已过 45 天
新鲜度 = 1 - (45/180) = 0.75  →  75%
```

**目标**：所有生产文档新鲜度 > 70%

---

## 内容生命周期模型

```
创建 → 审核 → 发布 → 维护 → 归档 → 退役
  │     │      │      │       │       │
  │     │      │    定期审核   │    最终移除
  │     │      │  每 90/180d  │
  │    SME/法务                │
  │   审批                   历史存档
  │
作者编写
```

**关键原则**：生命周期状态必须在元数据中跟踪。

---

## 内容新鲜度自动追踪

使用 DITA `critdates` 元素跟踪：

```xml
<prolog>
  <critdates>
    <created date="2025-01-15"/>
    <revised modified="2025-06-01"/>
    <metadata>
      <data name="review-cycle" value="180d"/>
      <data name="next-review" value="2025-12-01"/>
    </metadata>
  </critdates>
</prolog>
```

CI/CD 流水线定期扫描 `next-review` 字段，生成过期告警。

| 状态 | 新鲜度 | 动作 |
|------|--------|------|
| 🟢 正常 | > 80% | 无需操作 |
| 🟡 关注 | 60-80% | 自动通知负责人 |
| 🟠 警告 | 40-60% | 升级至团队领导 |
| 🔴 过期 | < 40% | 自动创建审核工单 |
| ⚫ 严重 | 0% (超过审核周期) | 标记为"未审核"，发布页面加横幅 |

## 练习 1：计算复用率

**场景**：某台工业机器人文档项目包含以下结构：

```
robot-safety-guide.ditamap → 引用 22 个主题
robot-operation-manual.ditamap → 引用 45 个主题
robot-maintenance-manual.ditamap → 引用 38 个主题
robot-parts-catalog.ditamap → 引用 60 个主题

去重后总主题数: 120 (topic-id 去重)
被 2+ 个映射引用的主题数: 48 (conref 不计)
被 3+ 个映射引用的主题数: 15
```

**任务**：
1. 计算基本复用率
2. 计算"高复用率"(3+ 映射引用)
3. 评估是否达到 35% 目标
4. 提出 3 条提升建议

---

## 练习 1 答案

```
1. 基本复用率 = 48 / 120 = 40.0%
2. 高复用率 = 15 / 120 = 12.5%
3. 已达成 35% 目标！

提升建议:
  1. 分析仅被 2 个映射引用的 33 个主题 (48-15)，
     寻找可以被更多产品线共享的机会
  2. 安全相关内容 (估计 8 个主题) 应被所有 4 个
     映射引用，提升高复用率
  3. 零件目录中的通用组件描述可提取为 conref 库，
     从文件级复用升级到元素级复用
```
