## 第一部分
### DITA 成熟度模型（L1-L5）

---

## 为什么需要成熟度模型？

```
成熟度模型帮助你回答三个核心问题：

  1. 我们现在在哪里？
     客观评估当前 DITA 实施水平

  2. 我们要去哪里？
     设定可量化的改进目标

  3. 我们怎么到那里？
     制定阶段性路线图
```

成熟度模型不是评判，而是**导航工具**——它告诉团队下一步应该往哪个方向走。

---

## DITA 成熟度五级模型概览

```
  L5: 优化级    持续改进 · AI 驱动 · 跨部门集成 · 知识图谱

  L4: 管理级    KPI 度量 · CI/CD 自动化 · 多语言发布 · 多团队协作

  L3: 定义级    标准化流程 · Conref 复用 · 多格式发布 · SubjectScheme

  L2: 可重复级   模板驱动 · 版本控制 · 基础验证 · 概念/任务/参考

  L1: 初始级    临时编写 · 无标准 · 个人依赖 · Word 文档
```

每一级是下一级的基础，不可跳跃。

---

## L1 — 初始级 (Initial)

**特征**：
- 文档编写完全依赖个人经验，无统一标准
- 使用 MS Word 等非结构化工具编写
- 没有版本控制或仅文件名版本号（`手册_v3_final_最终版.docx`）
- 文档审核通过邮件或纸质流转
- 内容复制粘贴是主要复用方式

**典型痛点**：
```
"这个操作手册和那个维护手册的安全部分要一致，
 但每次修改都要改两个地方..."
"找不到上一版的源文件了，从 PDF 反向还原吧"
"这个人和那个人写的格式完全不同"
```

---

## L1 升级到 L2 的关键行动

| 从 | 到 |
|----|----|
| Word 编写 | XML 结构化编写（DITA） |
| 文件名版本号 | Git 语义化版本 |
| 邮件审核 | 基础审批工作流 |
| 无编写标准 | DITA 模板体系 |
| 个人技能依赖 | 标准操作手册 (SOP) |

**最小可行行动 (MVA)**：
1. 选择一个试点产品（如 MC-5000）
2. 完成 DITA Novice 培训（全员）
3. 用 DITA 模板创建第一个结构化文档集
4. 建立 Git 仓库并制定贡献指南

---

## L2 — 可重复级 (Repeatable)

**特征**：
- 所有新文档使用 DITA 模板编写
- Git 管理所有源文件，有明确的提交规范
- DITA-OT 基础验证（`--validate`）纳入日程
- 团队掌握三大核心主题类型（Concept / Task / Reference）
- 使用 DITA Map 组织文档
- 基础元数据（作者、日期、产品）在每个主题中标注

**示例评估提示**：如果你已完成 Novice 培训并创建了第一个文档集，你在 L2。

---

## L3 — 定义级 (Defined)

**关键能力**：

| 领域 | L3 标志 |
|------|---------|
| **内容复用** | Conref 库建立，跨主题共享安全警告、公司信息 |
| **Keys** | DITA Map 全面使用 keydef/keyref，文件路径解耦 |
| **Subject Scheme** | 受控词表管控元数据（用户角色、文档状态、产品型号） |
| **Bookmap** | 印刷级 PDF 输出，封面/目录/索引完整 |
| **多格式发布** | HTML5 + PDF 双格式，一份源文件两种输出 |
| **标准化流程** | 主题编写、审核、发布的 SOP 文档化且全员遵循 |

**从 L2 到 L3 的特征**：从"能做事"到"有标准地做事"。

---

## L4 — 管理级 (Managed)

**关键能力**：

| 领域 | L4 标志 |
|------|---------|
| **KPI 度量** | 文档质量指标（缺陷率、更新时效、复用率）定期汇报 |
| **CI/CD 自动化** | 提交自动验证、构建、部署 |
| **本地化** | 多语言发布流程建立，XLIFF + CAT 工具集成 |
| **多团队** | 多产品线 / 多部门共用同一 DITA 框架 |
| **定制化** | 制造业专用主题类型、DITA-OT 插件按需开发 |
| **培训体系** | 新员工三天内可独立产出符合标准的主题 |

**从 L3 到 L4 的特征**：从"流程标准化"到"可度量、可预测"。

## L5 — 优化级 (Optimizing)

**特征**：
- **持续改进文化**：每次迭代都有可量化的改进目标
- **AI/ML 辅助**：自动分类、智能推荐复用片段、质量预检
- **知识图谱集成**：DITA 内容与 MES、PLM、ERP 系统双向连接
- **预测性分析**：基于用户行为数据预判哪些文档需要优先更新
- **自适应输出**：根据用户角色、设备、场景动态组装文档
- **社区贡献**：DITA 框架定制成果回馈开源社区

**L5 不是终点**——它是一个持续演进的状态。

## 路线图设计原则

| 原则 | 说明 |
|------|------|
| **SMART 目标** | Specific（具体）、Measurable（可衡量）、Achievable（可达成）、Relevant（相关）、Time-bound（有时限） |
| **渐进式递进** | 每月一个小胜利，每季度一个里程碑 |
| **80/20 法则** | 优先解决影响最大的 20% 问题 |
| **依赖管理** | 识别前置条件，避免空中楼阁 |
| **风险预留** | 每个季度留 1-2 周缓冲时间 |
| **持续验证** | 每个里程碑设置可验证的交付标准 |

<!-- _class: keypoint -->
> **路线图是活的文档**——每季度评审时更新，不是做一次管一年。

---

## 季度评审会议议程

| 环节 | 时长 | 内容 |
|------|------|------|
| **回顾** | 30 分钟 | 本季度目标完成情况、里程碑是否达成 |
| **数据** | 20 分钟 | KPI 仪表盘数据回顾（趋势图、环比分析） |
| **问题** | 30 分钟 | 未达标项目的根本原因分析（5 Whys 法） |
| **调整** | 30 分钟 | 根据实际情况微调下季度路线图 |
| **庆祝** | 10 分钟 | 肯定团队成就，分享最佳实践 |

## 关键 KPI 追踪

| KPI | 计算方式 | 目标方向 |
|-----|----------|----------|
| **主题复用率** | conref 引用主题数 / 总主题数 | 持续提升 |
| **内容缺陷密度** | 用户报告缺陷数 / 千词 | 持续下降 |
| **平均审核周期** | 提交审核到通过的中位数时间 | 持续缩短 |
| **首次通过率** | 首次审核即通过的主题比例 | 持续提升 |

## 反馈闭环模型

```
  用户反馈收集 → 分析分类 → 优先级排序 → 内容改进 → 用户验证 → 反馈收集
      ▲                                                              │
      └──────────────────────────────────────────────────────────────┘
                             （闭环迭代）
```

**核心理念**：用户反馈不只是"修 bug"，更是理解用户真实需求的窗口。

---

## 反馈收集渠道

| 渠道 | 适合人群 | 优点 | 缺点 |
|------|----------|------|------|
| **在线帮助反馈按钮** | 所有用户 | 覆盖广，即时有上下文 | 响应率低 |
| **定期用户访谈** | 深度需求挖掘 | 质量高，有洞察 | 成本高，样本小 |
| **支持工单分析** | 识别痛点 | 问题真实，优先级明确 | 偏负面 |
| **文档内评分** | 量化满意度 | 持续收集，趋势可见 | 不知道为什么打分 |
| **用户研讨会** | 战略方向 | 面对面深度交流 | 频率低 |

**示例适用组合**：在线帮助反馈按钮 + 支持工单分析（低成本高价值）。

---

## 反馈分类矩阵

| 优先级 | 类型 | 处理策略 |
|--------|------|----------|
| **P0 紧急** | 安全信息错误、关键步骤遗漏 | 24 小时内热修复 |
| **P1 高** | 技术参数错误、步骤描述不清 | 本周内完成修复 |
| **P2 中** | 缺少图表、示例不够 | 纳入下个迭代 |
| **P3 低** | 排版建议、风格偏好 | 季度整体优化 |
| **P4 建议** | 新功能建议、新文档需求 | 路线图讨论 |

## DITA 2.0 概览

DITA 2.0 是 DITA 标准的重大版本更新（2023 年进入委员会草案阶段，正式发布在即）。

**设计哲学**：
- **简化**：移除过时和冗余的特性
- **现代化**：更好的 HTML5 和 Web 支持
- **一致性**：统一过去 1.3 中不一致的设计模式
- **易用性**：降低入门门槛

**与 DITA 1.3 的关系**：不是替代，是演进。1.3 内容可以自动或半自动迁移到 2.0。

---

## DITA 2.0 关键变化

| 变化 | 旧 (1.3) | 新 (2.0) |
|------|----------|----------|
| `<shortdesc>` | 在 body 之前 | 仍是第一个 child，但允许更丰富的内容模型 |
| `<note>` type | warning, caution, danger 等多值 | 简化为统一模型 |
| 多媒体 | `<object>` 元素 | `<media>` 替代，支持 video/audio |
| 分类域 | `<data>` + outputclass 变通 | 标准化的 `<category>` 元素 |
| 元数据 | prolog 复杂结构 | 简化为 `<metadata>` |
| 主题约束 | DTD/XSD + 约束文件 | RNG (RELAX NG) 原生支持 |

---

## LwDITA：轻量级 DITA

**LwDITA (Lightweight DITA)** 是 DITA 2.0 的重要组成部分。为不熟悉 XML 的用户提供更简单的入门方式。

```
  完整 DITA XML               LwDITA
┌────────────────┐    ┌──────────────┐
│ 复杂元素嵌套    │    │ 简化元素集    │
│ 详细元数据      │    │ 基本元数据    │
│ 完整复用机制    │    │ 基础复用      │
│ 主题类型专用化  │    │ 三大核心类型  │
│ 庞大的 DTD/XSD  │    │ 精简 Schema   │
│ 需要 XML 编辑器 │    │ Markdown 支持  │
└────────────────┘    └──────────────┘
         ▲                      ▲
         │       互补关系        │
         └──────────────────────┘
```

---

## LwDITA 格式：XDITA 和 MDITA

### XDITA（简化 XML）
```xml
<topic id="dr5000-safety">
  <title>MC-5000 安全须知</title>
  <shortdesc>操作前必读安全信息。</shortdesc>
  <body>
    <p>MC-5000 配备三级安全防护...</p>
    <ul>
      <li>防撞联锁装置</li>
      <li>紧急停止系统</li>
    </ul>
  </body>
</topic>
```

比完整 DITA XML 更少元素，更易学习。

---

### MDITA（基于 Markdown）

```markdown
# MC-5000 安全须知

操作前必读安全信息。

MC-5000 配备三级安全防护：

- 防撞联锁装置
- 紧急停止系统
- 防护罩联锁

> **警告**: 操作前必须完成三级安全培训。
```

Markdown 作者可以用熟悉的格式编写，通过 DITA-OT 2.0 转换为完整 DITA 进行发布。

**1. DITA 成熟度 L3（定义级）的核心标志是什么？**

A. 有了 Git 版本控制

A. Create
B. Change
C. Check
D. Complete

**3. LwDITA 中的 MDITA 基于什么格式？**

A. JSON
B. XML
C. YAML
D. Markdown

**4. 季度评审中 "5 Whys" 法的主要目的是什么？**

A. 找责任人
B. 根本原因分析
C. 延长会议时间
D. 整理需求文档

**5. DITA 2.0 相比 1.3 的核心理念变化是什么？**

A. 更复杂
B. 更简化、现代化和一致性
C. 完全抛弃 XML
D. 只支持 PDF 输出

## 测验答案

| 题号 | 正确答案 | 说明 |
|------|----------|------|
| 1 | B | L3 的标志是流程标准化、Conref 复用和 SubjectScheme 的实施 |
| 2 | C | PDCA 是 Plan-Do-Check-Act，C = Check（检查） |
| 3 | D | MDITA 是 LwDITA 中基于 Markdown 的格式 |
| 4 | B | 5 Whys 是根因分析工具，通过连续追问找到问题本质 |
| 5 | B | DITA 2.0 的设计核心是简化、现代化和一致性 |
