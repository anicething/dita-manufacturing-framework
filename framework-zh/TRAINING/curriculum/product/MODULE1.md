## 文档体系结构

我们采用 **DITA** 标准（达尔文信息分类架构）编写文档。

您将遇到三种主题类型：

| 类型 | 用途 | 示例 |
|------|------|------|
| **概念（Concept）** | 解释"是什么"和"为什么" | 安全系统概述 |
| **任务（Task）** | 展示"怎么做" | 主轴校准流程 |
| **参考（Reference）** | 列出事实和数据 | 技术规格参数 |

> 文档通过 **地图（ditamap）** 组织章节结构和交叉引用。

## 安全互锁区域

| 区域 | 覆盖范围 | 触发动作 | 复位方式 |
|------|----------|----------|----------|
| **区域 1** | 主门及侧窗 | 主轴立即停止 + 轴保持 | HMI 手动复位 |
| **区域 2** | 上料区光幕 | 快速减速 ≤ 50 ms | 自动复位 |
| **区域 3** | 排屑器检修门 | 排屑器电机断电 | 现场手动复位 |
| **区域 4** | 冷却液箱检修口 | 冷却液泵停机 + 挂牌 | 钥匙锁定复位 |

> **⚠️ 严禁绕过安全互锁装置。** 任何故障应立即挂牌上报值班主管。

## 如何阅读概念（Concept）主题

示例：*MC-5000 安全系统概述*

```
concept id="dr5000-safety-system-zh"
├── title: "MC-5000 安全系统概述"
├── shortdesc: （一句话摘要）
├── prolog: （元数据 — 受众、产品、标准）
└── conbody:
    ├── section: 安全架构
    │   └── dl: 三层描述
    ├── section: 安全互锁区域
    │   └── simpletable: 区域详情
    └── section: 法规符合性
        └── ul: GB/T 标准列表
```

> **概念** = "是什么"和"为什么"。用于建立理解。

## 如何阅读任务（Task）主题

示例：*主轴激光校准*

```
task id="spindle-alignment-procedure-zh"
├── title: "使用激光校准仪调整 MC-5000 主轴"
├── prereq: （工具、安全条件）
└── taskbody:
    └── steps:
        ├── 步骤 1：准备机床
        ├── 步骤 2：安装激光靶
        ├── 步骤 3：执行测量
        ├── 步骤 4：调整主轴（含判定表）
        └── 步骤 5：验证校准
```

> **任务** = "怎么做"。按顺序执行步骤。每一步都有**执行结果**以确认操作成功。

## 如何阅读参考（Reference）主题

示例：*MC-5000 技术规格*

```
reference id="dr5000-specs-zh"
├── title: "MC-5000 技术规格"
└── refbody:
    ├── 主轴规格
    ├── 轴行程与进给速度
    ├── 工作台
```

> **参考** = 数据查询。用于查找规格、公差和要求。设计为快速浏览。

## 文档变更流程

如果发现错误或过时信息：

```
1. 在文档仓库中提交 GitHub Issue
2. 选择变更类型：
   - 轻微：错别字、格式
   - 中等：数值更新（如扭矩参数）
   - 重大：结构性变更
   - 关键：安全/合规相关
3. 分配给内容负责人（参见所有权矩阵）
4. 等待审核 — 通常 3-5 个工作日
5. 变更在下一个 CI/CD 周期发布
```

> **SLA：** 轻微变更 < 1 天，关键变更 < 48 小时（含强制等待期）

1. **概念**（是什么/为什么）、**任务**（怎么做）、**参考**（数据）
