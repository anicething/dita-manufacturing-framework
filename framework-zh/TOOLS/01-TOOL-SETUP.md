### 1.2 版本控制系统（源代码管理）

**用途：** 存储和管理 DITA 文件，保留变更历史

**可选方案：**

**安装检查清单：**
- [ ] 创建仓库
- [ ] 配置分支保护规则
- [ ] 设置团队权限

- [ ] 配置备份策略

**主要功能：**
- 版本控制与完整历史记录

- 审计日志
- 分支与合并
- 内容审阅工作流
- CI/CD 集成

**仓库结构：**
```
dita-content/
├── src/                      (DITA 源文件)
│   ├── shared/               (可重用内容库)
│   ├── product-a/
│   ├── product-b/
│   └── images/
├── references/               (集中式变量、法律声明、键定义)
├── output/                   (生成的输出文件 — 已加入 gitignore)
├── scripts/                  (构建与验证脚本)
├── ci-cd/                    (CI/CD 流水线定义)
├── build-config.xml          (DITA-OT 构建配置)
```

### 1.3 DITA Open Toolkit（发布引擎）

**用途：** 将 DITA 转换为 HTML、PDF、移动端格式

**费用：** 免费（开源）

**安装命令：**
```bash
# 下载最新版本 — 请查看 https://www.dita-ot.org/ 获取当前版本
wget https://github.com/dita-ot/dita-ot/releases/download/4.0/dita-ot-4.0.zip

# 解压
unzip dita-ot-4.0.zip

# 安装
cd dita-ot-4.0
./bin/dita install

# 验证
./bin/dita --version
```

**配置步骤：**
- [ ] 安装 DITA-OT 4.x
- [ ] 安装 PDF 插件（com.elovirta.pdf 或 org.dita.pdf2）
- [ ] 安装 HTML5 插件（已内置）
- [ ] 配置输出目录
- [ ] 在示例内容上测试转换

## 3. 安全最佳实践

**版本控制安全：**
- ✅ 为所有账户启用双因素认证（2FA）
- ✅ 使用 SSH 密钥（而非密码）
- ✅ 要求分支保护（禁止直接推送到主分支）
- ✅ 要求代码审查（合并前需 1 人以上批准）
- ✅ 启用审计日志
- ✅ 定期进行访问审查（每季度）

**文件安全：**
- ✅ 文档中不得包含密码
- ✅ 文件中不得包含 API 密钥
- ✅ 不得包含敏感的客户数据
- ✅ 加密 TMS 凭证
- ✅ 定期进行安全审计

## 4. 备份与恢复

### 4.1 备份策略

| 组件 | 备份方法 | 频率 | 保留期限 |
|------|---------|------|---------|
| 仓库 | Git clone --mirror | 每日 | 30 天 |
| DITA-OT 安装 | 可重新下载 | 安装时 | 不适用 |
| TMS 数据库 | 供应商管理 | 不适用 | 不适用 |
| 构建输出 | 从源码重新构建 | 按需 | 不适用 |

### 4.2 仓库备份

```bash
# 克隆完整仓库（含历史记录）
git clone --mirror <仓库地址> repo-backup.git

# 备份到本地
cp -r repo-backup.git /backup/location/$(date +%Y%m%d)
```

### 4.3 恢复流程

1. 确定丢失的内容
2. 检出之前的提交记录
3. 从备份创建新分支
4. 合并回主分支
