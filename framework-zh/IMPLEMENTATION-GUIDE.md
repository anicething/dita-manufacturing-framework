## 1. 概述

### 1.1 目的

本文档提供了一份**分步实施路线图**，用于帮助制造企业采用 DITA 制造框架。适用于从临时性文档实践过渡到结构化 DITA 信息环境的、50 人以上的制造企业团队。

### 1.2 实施阶段概览

| 阶段 | 名称 | 时长 | 关键交付物 |
|------|------|------|-----------|
| 0 | 现状评估 | 2 周 | 评估报告、差距分析 |
| 1 | 基础搭建 | 4 周 | 工具链、模板、治理 |
| 2 | 试点项目 | 6 周 | 一条产品线完成 DITA 转换 |
| 3 | 全面铺开 | 12 周 | 所有产品线完成迁移 |
| 4 | 运营 | 持续 | 成熟度提升 |

**预计总时间线：** 24 周（6 个月）达到全面投产。

### 1.3 前提条件

开始之前，需确保：

- 已获得高管层支持（预算、人员编制、时间线承诺）
- 已确定 DITA 卓越中心（CoE）核心团队
- 已选定至少一条产品线作为试点
- 团队对 XML 和结构化写作有基本了解

### 2.2 活动

|------|--------|------|------|

| 0.6 实施计划制定 | CoE 负责人 | 2 天 | 最终版路线图 |

针对每条产品线，评估：

- [ ] 现有文档总数
- [ ] 文档格式（Word、PDF、FrameMaker、HTML、其他）
- [ ] 支持的语言数量
- [ ] 现有模板使用情况（如有）
- [ ] 翻译工作流程（手动/TMS/混合）
- [ ] 存储和版本控制（共享文件夹/CMS/Git）

### 3.4 模板定制

在 12 个框架模板的基础上进行定制：

- [ ] 公司品牌标识（Logo、颜色、字体）
- [ ] 与 M1-M7 规则一致的元数据模式
- [ ] 将占位符替换为框架 key 的 keyref 引用
- [ ] 指向法律样板的 Conref 钩子
- [ ] 用真实产品样本替换示例内容
- [ ] 为产品变体设置 DITAVAL 条件

### 3.5 治理委员会启动

**DITA 治理委员会（DGC）— 首次会议议程：**

1. 审阅并签署治理章程
2. 批准内容所有权矩阵
3. 确定变更权限等级
4. 商定审校 SLA
5. 安排定期会议（每月）
6. 定义升级路径

### 3.6 阶段 1 关卡：工具链就绪

**标准：**
- 至少有一名作者能使用模板创建主题并生成 HTML5/PDF
- CI/CD 流水线成功构建示例项目
- 治理委员会已举行首次会议
- 核心团队已完成实操培训
- 仓库结构已建立并可访问

## 4. 阶段 2：试点项目（第 7-12 周）

### 4.1 目标

- 将一条产品线迁移到 DITA
- 用真实内容验证框架
- 通过实际生产培训写作人员
- 建立并校准指标

### 4.2 活动

| 活动 | 负责人 | 时长 | 周次 | 产出 |
|------|--------|------|------|------|
| 2.1 试点启动 | CoE 负责人 | 1 天 | W7 | 确认试点团队和范围 |
| 2.2 内容迁移 | 团队 + SME | 3 周 | W7-9 | 约 50 个 DITA 主题 |
| 2.3 审校流程测试 | 团队 | 1 周 | W10 | PR 工作流已验证 |
| 2.4 首次发布 | IT 负责人 | 1 周 | W11 | HTML5 + PDF 输出 |
| 2.5 试点复盘 | CoE 负责人 | 2 天 | W12 | 经验教训报告 |

### 4.3 内容迁移策略

对现有内容采用**分诊法**：

| 优先级 | 内容类型 | 操作 | 理由 |
|--------|---------|------|------|
| P1 | 安全文档 | 直接用 DITA 创建 | 合规关键，常需重写 |
| P2 | 最频繁更新的文档 | 迁移到 DITA | 复用的高投资回报率 |
| P3 | 安装与操作手册 | 迁移到 DITA | 核心产品文档 |
| P4 | 参考规格 | 直接用 DITA 创建 | 易于重新录入 |
| P5 | 很少更新的历史内容 | 以原始格式归档 | 迁移投资回报率低 |

### 4.4 试点团队组成

| 角色 | 人力 | 来源 |
|------|------|------|
| 内容架构师/主管 | 1 | CoE 核心 |
| 技术写作人员 | 2-3 | 文档团队 |
| 主题专家（SME） | 0.5 | 产品工程 |
| IT 支持 | 0.25 | IT 部门 |
| 审校人员 | 0.25 | 跨团队 |

### 4.5 试点期间跟踪的指标

- 每周创建的主题数
- 复用率（conref + keyref 主题数 / 主题总数）
- 构建成功率
- 审校周期（PR 从打开到合并的平均时间）
- 团队信心调查评分
- 可供翻译的内容量（字数）

### 4.6 常见试点陷阱与应对

| 陷阱 | 信号 | 应对措施 |
|------|------|---------|
| 范围蔓延 | "顺便把 X 产品也迁移了吧" | 启动时锁定试点范围 |
| 模板迭代 | "这个元素应该改成别的" | 记录改进项，阶段 3 实施 |
| SME 不可用 | 审校受阻 | 通过 DGC 升级；预留 SME 时间 |
| 工具问题 | 作者退回 Word | IT 与写手结对；每日站会 |
| 完美主义 | "这还不够 DITA 规范" | 80% 原则：先发布，后打磨 |

### 4.7 阶段 2 关卡：试点验证通过

**标准：**
- 试点主题已发布并获利益相关方批准
- 团队能独立编写和发布 DITA 主题
- 构建流水线稳定（成功率 90%+）
- 模板问题已记录并排定优先级
- 试点复盘已完成并有可执行项

### 5.3 活动

| 活动 | 负责人 | 时长 | 周次 |

| 3.4 第 2 波迁移 | 写手团队 | 3 周 | W17-19 |

| 3.6 第 3 波迁移 | 全员 | 4 周 | W21-24 |
| 3.7 质量框架搭建 | 内容架构师 | 2 周 | W23-24 |

### 5.4 培训规模扩展

| 培训批次 | 时间 | 对象 | 形式 |
|---------|------|------|------|
| 第 1 批（核心） | 阶段 1 | CoE + 试点写手 | 线下，1 周 |
| 第 2 批 | 阶段 3 第 1 波 | 其余写手 | 混合式，1 周 |
| 第 3 批 | 阶段 3 第 2 波 | 新人 + SME | 自学，持续 |
| 持续培训 | 阶段 4 起 | 全员 | 月度工作坊 |

### 5.5 翻译工作流

```
源主题 (EN) → 
  导出 XLIFF →
    翻译 (TMS) →
      导入 XLIFF →
        目标主题 (zh-CN, de, fr, ...) →
          验证 →
            发布
```

**翻译就绪检查清单：**
- [ ] 在 DITA-OT/oXygen 中配置了 XLIFF 导出
- [ ] TMS（翻译管理系统）已连接
- [ ] 翻译记忆库已建立
- [ ] 术语数据库已创建（来自 glossary 主题）
- [ ] 各语言的 DITAVAL 条件已定义
- [ ] 翻译审校流程已定义
- [ ] 基于 key 的变量标记为"不翻译"

### 5.6 阶段 3 关卡：全面投产

**标准：**
- 所有产品线均有 DITA 文档
- 80% 以上的写手活跃使用 DITA
- 翻译流水线可运作
- 正在收集质量指标
- 构建流水线完全自动化
- 文档按计划发布

## 6. 阶段 4：运营与持续改进（第 25 周+）

### 6.1 目标

- 维护和改进 DITA 系统
- 跟踪并优化 KPI
- 持续演进框架
- 指导新团队成员

### 6.2 运营节奏

| 频率 | 活动 | 负责人 |
|------|------|--------|
| 每日 | 自动构建 + 发布 | CI/CD（自动） |
| 每周 | 内容质量抽查 | 内容架构师 |
| 双周 | 写手答疑/诊所 | 培训负责人 |
| 每月 | DGC 会议 | CoE 负责人 |
| 每月 | KPI 仪表盘评审 | 内容架构师 |
| 每季 | 框架发布 | CoE 负责人 |
| 每季 | 培训需求评估 | 培训负责人 |
| 每年 | 完整成熟度评估 | CoE 负责人 + DGC |

### 6.3 KPI 仪表盘

每月跟踪以下指标：

| KPI | 目标值 | 测量方法 |
|-----|--------|---------|
| 复用率 | ≥ 35% | conref + keyref 主题数 / 主题总数 |
| 构建成功率 | ≥ 95% | 成功构建数 / 构建总数 |
| 按时发布率 | ≥ 90% | 按时发布数 / 发布总数 |
| 审校周期 | ≤ 3 天（小改），≤ 10 天（大改） | PR 从打开到合并 |
| 翻译周期 | ≤ 5 天 / 1,000 词 | TMS 数据 |
| 写手熟练度 | 按批次设定目标 | 内部评估 |
| 主题质量分 | ≥ 80% | Schematron + 人工审计 |
| 用户满意度 | ≥ 4.0 / 5.0 | 年度调查 |

### 6.4 框架版本管理

| 版本 | 频率 | 内容 | 流程 |
|------|------|------|------|
| v1.x（补丁） | 每月 | Bug 修复、小模板更新 | DGC 批准，1 周评审 |
| v2.x（小版本） | 每季 | 新模板、工具链更新 | DGC + 试点，1 月评审 |
| v3.x（大版本） | 每年 | 破坏性变更、DITA-OT 升级 | 完整评估，3 月评审 |

### 6.5 成熟度模型

每年用此模型评估进展：

| 等级 | 名称 | 特征 |
|------|------|------|
| 1 | 临时级 | 无 DITA，手动发布，无复用 |
| 2 | 已定义级 | 已采用 DITA，模板使用中，基本复用 |
| 3 | 已管理级 | 有指标跟踪，CI/CD，翻译工作流 |
| 4 | 已度量级 | KPI 已优化，自动化质量关卡 |
| 5 | 已优化级 | AI 辅助写作，持续创新 |

**第 1 年目标：** Level 2
**第 2 年目标：** Level 3
**第 3 年目标：** Level 4

## 8. 风险登记册

| 风险 | 概率 | 影响 | 缓解措施 | 应急方案 |
|------|------|------|---------|---------|
| 写手接受度低 | 中 | 高 | 强力培训、持续支持、同伴榜样 | 绩效管理 |
| 工具链问题 | 中 | 高 | 阶段 1 充分测试；IT 待命 | 回退到 oXygen 独立版 |
