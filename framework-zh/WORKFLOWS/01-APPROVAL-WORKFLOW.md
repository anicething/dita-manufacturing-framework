## 1. 十步审批流程

```
1. 计划 (PLAN)
   ↓ 作者创建工作项
   ↓
2. 起草 (DRAFT)
   ↓ 作者在 Git 功能分支中创建主题
   ↓
3. 自审 (SELF-REVIEW)
   ↓ 作者执行质量检查清单
   ↓
4. 主题专家审核 (SME REVIEW)（2 个工作日）
   ↓ 主题专家验证技术准确性
   ↓
5. 合规检查 (COMPLIANCE CHECK)（1 个工作日）
   ↓ 合规官审核 ISO/法律要求
   ↓
6. 编辑审核 (EDITORIAL REVIEW)（1 个工作日）
   ↓ 架构师/高级作者审核结构和风格
   ↓
7. 最终批准 (FINAL APPROVAL)（1 个工作日）
   ↓ 产品经理批准发布
   ↓
8. 发布 (PUBLISH)
   ↓ 自动合并到主分支，触发 CI/CD
   ↓
9. 分发 (DISTRIBUTE)
   ↓ 多渠道发布（Web、PDF、移动端）
   ↓
10. 本地化 (LOCALIZE)
    ↓ 自动提取用于翻译
    ↓ 完成
```

**总发布时长：< 8 个工作日**

## 2. Git 工作流

### 2.1 分支策略

**主分支：** 生产就绪内容

**功能分支：** `feature/{product}/{topic-id}`

```bash
# 创建功能分支
git checkout -b feature/product-a/c-overview

# 处理内容
git add topics/c_overview.dita
git commit -m "Draft: Product A Overview topic"

# 推送到远程仓库
git push origin feature/product-a/c-overview

# 创建 Pull Request（用于审核）
```

### 2.2 Pull Request 模板

```markdown
## 主题信息
- **文档编号：** [例如：DOC-PROD-001-v1.0]
- **主题 ID：** [例如：c_overview]
- **产品：** [产品 A/B/C]
- **受众：** [管理员/用户/开发者/高管]
- **状态：** [草稿/准备审核]

## 变更摘要
- 简要描述本主题涵盖的内容
- 为什么需要此主题
- 任何相关主题

## 检查清单
- [ ] 元数据完整
- [ ] 无拼写错误
- [ ] 无损坏链接
- [ ] 图片已优化并包含替代文本
- [ ] 遵循风格指南
- [ ] 符合 ISO 要求
- [ ] 准备进行主题专家审核

## 需要审核人员
- [ ] @subject-matter-expert
- [ ] @compliance-officer
- [ ] @architect
- [ ] @product-manager
```

## 3. 审核阶段

### 阶段 1：自审（作者）

**作者检查项：**
- [ ] 元数据完整
- [ ] 无拼写错误
- [ ] 语法正确
- [ ] 无损坏链接
- [ ] 图片存在且已优化
- [ ] 主题结构正确
- [ ] 遵循风格指南
- [ ] 无敏感信息
- [ ] 准备进行同行评审

### 阶段 2：主题专家审核（2 个工作日）

**主题专家验证：**
- [ ] 技术准确性
- [ ] 信息完整性
- [ ] 术语正确
- [ ] 无冲突信息
- [ ] 示例正确
- [ ] 前提条件准确
- [ ] 预期结果准确

**反馈选项：**
- ✅ 通过
- ✅ 通过（含建议）
- ⚠️ 需要修改
- ❌ 拒绝

### 阶段 3：合规审核（1 个工作日）

**合规官检查：**
- [ ] 符合 ISO 27001 要求
- [ ] 符合 ISO 9001 要求
- [ ] 符合 ISO 14001 要求
- [ ] 未泄露机密信息
- [ ] 法律免责声明已存在（如需要）
- [ ] 安全警告得当
- [ ] 隐私要求已满足
- [ ] 文档可追溯性完整

### 阶段 4：编辑审核（1 个工作日）

**架构师/高级作者审核：**
- [ ] 结构与主题类型模板匹配
- [ ] 元数据与标准一致
- [ ] 风格指南合规
- [ ] 术语一致
- [ ] 已识别重用机会
- [ ] 交叉引用恰当
- [ ] 写作便于本地化
- [ ] 质量水平符合标准

### 阶段 5：最终批准（1 个工作日）

**产品经理批准：**
- [ ] 与产品策略一致
- [ ] 满足客户需求
- [ ] 发布时间适当
- [ ] 业务需求满足
- [ ] 质量可接受

**最终批准决定：**
- ✅ 批准 — 准备发布
- ⏸️ 暂缓至后续版本
- ❌ 无法批准

## 4. 升级流程

若审核受阻：

```
审核逾期？
  ↓
1. 向审核人员发送提醒邮件（逾期 1 个工作日）
  ↓
2. 升级至审核人员的经理（逾期 2 个工作日）
  ↓
3. 升级至技术传播总监（逾期 3 个工作日）
  ↓
4. 文档治理委员会在月度会议上解决（逾期 4 天以上）
```
