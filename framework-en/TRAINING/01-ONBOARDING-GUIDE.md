# Onboarding Guide - 4 Week Program

**Document ID:** TRN-001  
**Version:** 1.0  
**Last Updated:** 2026-06-06  
**Status:** Approved  

---

## Overview

This 4-week program trains new writers on DITA fundamentals, style guide, tools, and processes.

**Total Hours:** 40 hours  
**Time Commitment:** 8-10 hours per week  
**Format:** Mix of classroom, hands-on, and self-study  

---

## Week 1: DITA Fundamentals (10 hours)

### Monday: Introduction (2 hours)
- What is DITA and why we use it
- Three topic types: Concept, Task, Reference
- DITA vs traditional documentation
- Benefits for manufacturing: Reuse, localization, compliance

**Activity:** Review sample DITA topics from your product

### Tuesday-Wednesday: Topic Structure (4 hours)
- Concept topic structure and examples
- Task topic structure and examples
- Reference topic structure and examples
- When to use each type

**Activity:** Identify topic types in existing documentation

### Thursday: DITA Elements (2 hours)
- Common DITA elements: `<topic>`, `<section>`, `<p>`, `<ul>`, `<table>`
- Metadata: what it is and why it matters
- Validation: how to check your topics

**Activity:** Create first simple topic

### Friday: Maps & Organization (2 hours)
- DITA maps: how topics are organized
- Navigation structure
- Cross-references and links
- Reuse concepts

**Activity:** Create a simple map with 3 topics

---

## Week 2: Style Guide & Standards (10 hours)

### Monday: Writing Standards (2 hours)
- Tone and voice for manufacturing
- Clarity, conciseness, consistency, compliance
- Target audience: admins, users, developers
- Global audience considerations

**Activity:** Edit sample topics for style compliance

### Tuesday: Formatting & Terminology (2 hours)
- Headings, lists, tables, emphasis
- Approved terminology for your products
- Warnings, cautions, notes
- Images and screenshots

**Activity:** Format sample content correctly

### Wednesday: Procedures & Code (2 hours)
- How to write task topics properly
- Step-by-step structure and examples
- Code blocks and inline code
- Localization-friendly writing

**Activity:** Write a simple 3-step procedure

### Thursday: Quality Checklist (2 hours)
- Quality checklist review
- Metadata requirements
- Common mistakes to avoid
- Accessibility and compliance

**Activity:** Self-review a sample topic

### Friday: Quiz & Review (2 hours)
- Written assessment (20 questions)
- Review key concepts
- Q&A with senior writer
- Preparation for tool training

---

## Week 3: Tools Training (10 hours)

### Monday: oXygen XML Editor (3 hours)
- Installation and setup
- Creating new topics
- Validating XML
- Publishing to HTML/PDF
- Version control integration

**Activity:** Create topic in oXygen and publish

### Tuesday: Version Control with Git (3 hours)
- Git basics and workflow
- Creating branches
- Committing changes
- Pull requests and reviews
- Branch protection rules

**Activity:** Submit first change for review

### Wednesday: CI/CD Pipeline (2 hours)
- How automated publishing works
- CI/CD pipeline overview
- Build logs and troubleshooting
- Multi-channel publishing

**Activity:** Observe your first automated publish

### Thursday: Localization & Search (2 hours)
- How content gets translated
- Translation memory
- Search indexing
- Multi-language portal

**Activity:** Review translated content from TMS

---

## Week 4: Hands-On Project (10 hours)

### Monday: Project Assignment (2 hours)
- Assign real product documentation task
- Review requirements and acceptance criteria
- Discuss with SME and product manager
- Plan your work

### Tuesday-Wednesday: Creation (4 hours)
- Create 2-3 actual topics for your product
- Follow all standards and guidelines
- Include proper metadata
- Add cross-references

### Thursday: Submission & Review (2 hours)
- Submit PR with topics
- Participate in code review feedback
- Make requested changes
- Merge to production

### Friday: Certification (2 hours)
- Assessment completed
- Feedback discussion
- Certification approved
- Ready for independent work!

---

## Assessment Criteria

**Written Test (25 points)**
- DITA fundamentals: 10 points
- Style guide knowledge: 10 points
- Process understanding: 5 points
- **Pass:** 20/25 (80%+)

**Practical Project (25 points)**
- Topic quality: 10 points
- Metadata completeness: 5 points
- Style guide compliance: 5 points
- Reusability/structure: 5 points
- **Pass:** 20/25 (80%+)

**Attendance & Participation (10 points)**
- Attendance: 5 points (must attend 90%+)
- Participation: 5 points (active questions/discussions)
- **Pass:** 8/10 (80%+)

---

## Certification

**Writers are certified when:**
- [ ] All training sessions completed (38+ hours)
- [ ] Written test passed (80%+)
- [ ] Practical project completed successfully
- [ ] First 3 topics reviewed and approved
- [ ] Signed understanding of governance policies
- [ ] Passed tool proficiency check

**Upon Certification:**
- ✅ Approved to author topics independently
- ✅ Added to approval workflows
- ✅ Access to shared content repository
- ✅ Invited to monthly best practices meetings

---

## Post-Training Support

**Week 5+:**
- Paired with senior writer mentor (4 weeks)
- Weekly check-in meetings
- Code review feedback on first 10 topics
- Access to training materials and templates
- Monthly continuing education (1 hour)

**Annual Recertification:**
- 4-hour refresher training
- Updated on process changes
- Best practices review
- Q&A with leadership
